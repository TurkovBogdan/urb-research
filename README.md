# urb-research

> Долговременная память исследований для ИИ-агента. Агент ищет в вебе, отбирает источники и пишет разбор со ссылками на них; человек читает готовый документ в веб-интерфейсе.

Приложение состоит из двух половин. Первая — **MCP-сервер**: тридцать инструментов, которыми агент ведёт исследование. Вторая — **веб-интерфейс**: всё, что агент создал, тут же становится страницей, которую можно открыть, прочитать и сохранить в PDF. Это не черновик в чате, который исчезнет вместе с сессией, а документ, который останется в базе и переживёт агента.

## Как идёт исследование

Агент работает по конвейеру, заданному инструкциями самого MCP-сервера.

1. **Заводит исследование** — тему целиком.
2. **Делит её на зоны** — тематические направления, они же разделы будущего отчёта. У зоны есть бриф: задача, границы, ожидаемый результат.
3. **Запускает поиски по зоне.** Движок поиска отдаёт ссылки, приложение скачивает страницы и приводит их к markdown. Каждая найденная страница становится источником со статусом «не разобран».
4. **Разбирает каждый источник:** читает текст целиком и выносит решение — принять или отсеять, с оценкой от 1 до 10 и причиной. Источник, чья страница не скачалась, отмечен ошибкой; его материал можно дотянуть повторно.
5. **Пишет синтез зоны** и ссылается на принятые источники их кодами. Код, набранный прямо в тексте, превращается в ссылку на карточку источника: читатель переходит от утверждения к доказательству одним кликом.
6. **Собирает исследование из зон.** Всё, что не легло ни в одну зону, уходит в заметки шести видов: вывод, идея, вопрос, наблюдение, методическое решение, уточнение от пользователя.

У каждой сущности свой код с префиксом — `RESEARCH@`, `AREA@`, `QUERY@`, `SOURCE@`, `NOTE@`, `GROUP@`. Код — и адрес страницы, и ссылка внутри текста, и аргумент любого инструмента.

## Что умеет агент

Тридцать MCP-инструментов, пять поверхностей.

- **Реестр.** Исследования, зоны, заметки и группы: создать, прочитать, перечислить, изменить. Удаление — один инструмент на все типы, каскад задаётся префиксом кода: с исследованием уходят его зоны, поиски, источники и заметки, с группой — ничего: её исследования остаются и выходят из папки.
- **Поиск и источники.** Запуск поиска по зоне, список поисков исследования или зоны, список источников с фильтром по статусу, чтение источника вместе с текстом страницы, повторное скачивание материала (до шести кодов за вызов), рецензия. Источники берутся только из поиска — добавить ссылку руками нельзя.
- **Редактор тела.** Правка по месту вместо переписывания документа целиком: заменить всё тело, заменить точную строку, заменить раздел по заголовку, вставить текст в начало, в конец или к якорю. В ответ приходит не документ, а шов правки — по 128 символов текста с каждой стороны, там и видно, что склеилось не так.
- **Справочники сервера.** Сервер хранит инструкции по форматам, которые принимает: разметка тела (как код становится ссылкой, какой markdown рисуется) и схемы mermaid (какие типы диаграмм рендерятся и каким синтаксисом). Агент читает их перед работой, а не после неудачи.
- **Показ пользователю.** Инструмент открывает страницу любой сущности в браузере — вместо пересказа агент кладёт артефакт на экран.

## Веб-интерфейс

- **Исследования** и **Группы** — список исследований со счётчиками зон, поисков, принятых и отсеянных источников; поиск по названию, описанию и текстам, отдельно — по всему скачанному материалу источников. Карточка исследования собирает зоны, поиски, источники и заметки; отсюда же документ скачивается в PDF. Тексты пишет агент, человеку остаются название, описание, группа, удаление и повторное скачивание источников.
- **Веб-поиск** — сырой слой под исследованиями: прогоны поиска с их параметрами и выдачей, сохранённые страницы с текстом в markdown.
- **Интеграции** — подключения к внешним сервисам, их состояние и остаток на балансе.
- **Модули** — настройки работы: какой движок ищет, какой скачивает страницы, сколько результатов на запрос, какие лимиты параллельности.
- **Интерфейс** — тема, шрифты, оформление текста документа, блоков кода и схем.
- **Задачи** — фоновые задачи, их запуски и логи (только чтение).
- **Сервер** — правка `.env` прямо из интерфейса с перезапуском процесса.
- **MCP-серверы** — что поднято как MCP-сервер, его инструкции, список инструментов и готовый конфиг подключения.
- **Версия и обновление** — версия установки, отставание от ветки и кнопка обновления.

## Требования

Нужны **git** и **uv**; Python, зависимости и базу приложение приносит само.

Git ставится менеджером пакетов системы — `apt`, `dnf`, `brew`. Про uv можно не думать: `./install.sh` предложит поставить его официальным установщиком Astral, а тот заодно скачает нужный Python (3.12, версия зафиксирована в `.python-version`).

Базу данных ставить не нужно: по умолчанию используется **SQLite** — один файл, без сервера. PostgreSQL — опция для боевого масштаба (нужен сервер 14+ с созданными базой и пользователем).

Чтобы искать в вебе, понадобится ключ хотя бы одного поискового сервиса. Для установки и осмотра интерфейса он не нужен.

## Установка

```bash
git clone https://github.com/TurkovBogdan/urb-research.git && cd urb-research
./install.sh
```

Скрипт проверяет инструменты, ставит зависимости и запускает приложение — дальше остаётся открыть интерфейс. Повторный запуск безопасен: он синхронизирует зависимости и поднимает приложение заново.

> Пакеты ставятся готовыми бинарными сборками — компилятор и системные dev-библиотеки не нужны. То же самое руками: `uv sync --all-groups`, затем `./run.sh`.

**Файл `.env` писать не нужно.** Его не существует до первого запуска: приложение создаёт его само со значениями по умолчанию (режим `prod`, SQLite в `runtime/prod/app.sqlite3`) и выписывает себе два секрета — токен MCP-серверов и мастер-ключ шифрования доступов в базе. Дальше файл правится на странице «Сервер» или руками; образец с комментариями — `.env.example.prod`.

Схема базы разворачивается сама **только на первом запуске, на пустой базе**. Дальше миграции накатывает обновление (`./update.sh`), а не старт приложения: база, отставшая от кода, встречает заглушкой со списком неприменённых ревизий.

## Запуск

```bash
./run.sh
```

Скрипт поднимает бекенд с фоновым обработчиком в одном процессе и открывает браузер, как только приложение ответит. Тем же заканчивается `./install.sh`. Адрес берётся из `.env` (`SERVER_HOST` / `SERVER_PORT`, по умолчанию `http://127.0.0.1:13410`).

Остальные команды:

```bash
./run.sh stop        # погасить установку (только её процессы, соседние не трогает)
./run.sh test        # прогнать тесты; аргументы пробрасываются: ./run.sh test --core
./run.sh help        # справка
```

То же самое без обёртки — `uv run python src/app.py --backend --worker`. Флаги `--backend` (HTTP-сервер) и `--worker` (фоновые задачи) можно развести по разным процессам; в одном процессе указываются оба.

## Подключение агента

Держать сервер запущенным вручную не нужно. MCP-клиент подключается через **stdio-шим**: клиент сам запускает процесс при открытии сессии, тот поднимает бекенд, открывает браузер на главной и передаёт ему вызовы инструментов. Бекенд переживает сессию: следующая подключится к уже работающему.

Готовый конфиг лежит на странице **«MCP-серверы»**: он уже содержит абсолютные пути этой установки и токен. Скопируйте его в настройки клиента (Claude Desktop, Claude Code). Выглядит он так:

```json
{
  "mcpServers": {
    "research": {
      "command": "/path/to/uv",
      "args": [
        "run", "--directory", "/path/to/urb-research",
        "python", "src/app.py", "--mcp-stdio", "research"
      ],
      "env": { "MCP_TOKEN": "<токен из .env>" }
    }
  }
}
```

> Путь к `uv` и к проекту (`--directory`) — **абсолютные**. Многие MCP-клиенты стартуют из своего каталога с урезанным PATH, и без `--directory` uv не найдёт проект: «Connection Failed».

## Ключи внешних сервисов

Ключи задаются не в `.env`, а в интерфейсе, на странице **«Интеграции»**. Хранятся в базе зашифрованными мастер-ключом из `.env` — копия базы без него бесполезна.

Подключить можно пять сервисов:

| Сервис | Что делает |
|---|---|
| Tavily | веб-поиск и извлечение контента страниц |
| Firecrawl | скрапинг, поиск и обход сайтов |
| xAI (Grok) | агентский веб-поиск и поиск по X |
| OpenRouter | единый API-шлюз к языковым моделям |
| UroborosWebScrapper | локальный сервис скрапинга через анонимный браузер |

Модуль веб-поиска различает две роли и настраивается на странице «Модули» отдельно по каждой: **кто ищет** (Tavily, Firecrawl, Grok) и **кто скачивает страницы** (Tavily, Firecrawl, UroborosWebScrapper). По умолчанию обе роли у Tavily — начать можно с одного ключа.

## Обновление

```bash
./update.sh            # обновить
./update.sh --dry-run  # показать, что будет сделано, ничего не трогая
```

Команда останавливает работающие экземпляры MCP-сервера, на время работы запрещает поднимать новые и обновляет установку. То же самое делает кнопка «Обновить» на странице «Версия и обновление»: там же видно, на сколько коммитов установка отстала.

## Структура

```
├── src/       # код: app.py (точка входа), core/ (платформа), modules/ (домены)
├── web/       # интерфейс на Vue 3; web/dist/ — собранный SPA, лежит в репозитории
├── runtime/   # данные работающего приложения: база, кеш, логи, резервные копии
├── tests/     # тесты
└── dev/       # конфигурации запуска для IDE и локальные стенды
```

Модулей семь: `research` (реестр исследований и MCP-сервер), `web_search` (поиск и сохранение страниц), `core_connectors` (доступы к внешним сервисам), `core_setup` (правка `.env`), `core_interface` (настройки оформления), `core_monitoring` (задачи), `core_mcp` (интроспекция MCP-серверов).

## Разработчику

```bash
./run.sh dev         # Vite с HMR + бекенд с hot-reload (нужны Node.js 20+ и pnpm)
./run.sh build-prod  # пересобрать фронт в web/dist
./run.sh test --core # тесты ядра; полный прогон — ./run.sh test --all
```

Как устроены тесты и какие флаги они понимают — [`tests/README.md`](tests/README.md).
